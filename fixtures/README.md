# fixtures

Language-neutral test data, for the same reason `protocol/` exists: more than one
implementation has to agree about something, and agreement that nothing checks
is agreement that quietly stops being true.

## `wakeword/`

Golden vectors for the openWakeWord streaming feature pipeline, generated by
[`client/tools/make_golden_vectors.py`](../client/tools/make_golden_vectors.py).

| File | What it is |
|---|---|
| `input.wav` | 3.84 s of 16 kHz mono 16-bit PCM — 48 capture blocks exactly |
| `golden.json` | Per-block intermediate tensors, stage probes, and gating traces |

### Why

The Android client reimplements the pipeline in Kotlin. That pipeline is the one
part of the port whose bugs are **silent**: a wrong buffer offset or a dropped
transform produces plausible scores that never cross threshold, and the only
symptom is a wake word that doesn't work. Nothing throws, nothing logs.

So the generator does two things. It reimplements the streaming algorithm from
scratch against raw ONNX Runtime — using only the steps written down in
[`android-client-plan.md`](../android-client-plan.md), never openWakeWord's own
buffering — and then it **cross-checks that reimplementation against the real
`openwakeword.Model`, block for block**, refusing to write the fixture if they
disagree. At the time of writing they agree exactly: worst disagreement `0.0`
across all 48 blocks and both models.

That check is the point. It proves the written-down algorithm *is* the library's
algorithm, on the desktop, in the language where a difference can be debugged —
rather than discovering it from Kotlin later with no reference to compare
against.

### What's in `golden.json`

- **`blocks[]`** — one entry per 80 ms block: mel frame count, both buffer
  depths, the full 96-dim embedding, raw and gated classifier scores, and the
  VAD score. Enough to localize a divergence to a single stage.
- **`melSlabs`** / **`vadSlabs`** — full mel and per-VAD-frame arrays for six
  sampled blocks, separating a framing bug from a state-carry bug.
- **`probes`** — each stage driven directly with a fixed input chosen to land
  mid-range. These exist because the synthetic signal is not a wake word, so
  every score in `blocks[]` sits near zero and a port whose classifier always
  returned `0.0` would match them. The classifier probe lands at 0.63 and 0.97,
  above both thresholds, so it exercises the detection path too.
- **`models`** — the SHA-256 of each of the five `.onnx` files the numbers were
  generated from. Every value here is a function of those weights, so a port
  checked against a differently-versioned model would fail as numeric noise with
  nothing pointing at the cause. `ModelIdentityTest` verifies the copies in
  `android/models/` against these digests before any comparison runs.
- **`probes.gating`** — a scripted score sequence through the warmup and
  refractory logic: five zeroed warmup frames, a fire, two suppressed frames
  inside the refractory window, and a re-arm once it clears. The audio fixture
  gives no coverage here at all, and this is where the port is most likely to go
  subtly wrong.

### Who checks against it

[`android/core`](../android/core) — the Kotlin feature pipeline, under plain JVM
unit tests (`cd android && ./gradlew :core:test`). It runs the same ONNX Runtime
version the generator did, against the same weights, so the tests allow no
tolerance beyond the fixture's own six-decimal rounding: 1e-6.

The worst disagreement observed across every comparison — mel frames,
embeddings, classifier scores, VAD probabilities — is **4.999e-07**, which *is*
the rounding half-step. The two implementations agree as exactly as this file is
capable of recording.

### Determinism

`AudioFeatures.__init__` seeds its feature buffer with four seconds of
`np.random.randint` audio, so the library's first ~16 blocks are not reproducible
between runs. The generator seeds with four seconds of **silence** instead and
forces the same seeding on the library before comparing. **The Kotlin port must
do the same.** After ~16 blocks the seed frames have been pushed out of the
16-frame classifier window and the choice stops mattering, but matching it makes
the fixture exact from block 0 rather than only eventually.

The fixture is byte-identical across runs. If regenerating produces a diff, the
pipeline changed — that is the fixture doing its job, not noise to paper over.

### Known limitation

`input.wav` is synthetic: a chirp, tone mixtures, a noise floor, a burst train,
and digital silence at both ends. It exercises the whole filterbank but contains
no speech, so it pins the **arithmetic** and not detection *behaviour*. Whether
"hey jarvis" actually fires on an Android capture chain is a Phase 5 tuning
question and needs a real recording.

Once one exists, regenerate against it — the format is unchanged and the
cross-check still applies:

```sh
cd client
.venv/bin/python tools/make_golden_vectors.py --input path/to/hey_jarvis.wav
```

### Regenerating

```sh
cd client
.venv/bin/python tools/make_golden_vectors.py
```

Needs the client venv and the downloaded openWakeWord models — see
[`client/README.md`](../client/README.md).
